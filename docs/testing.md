# 测试指南

本仓库**没有自动化测试**:`build.gradle` 未注册任何测试任务,`src/` 下也没有测试源码(`test` 只是 Java 插件的默认空壳)。改动后的验证方式是:先 `.\gradlew.bat compileJava`(或 `clean deploy`)确认编译通过,再按下面的手测清单逐项核对。

差异渲染高度依赖游戏运行时的 UI 布局测量,不适合离线断言;若未来补充自动化,只考虑纯函数逻辑(颜色解析、数字/堆叠文本解析等),且不得影响单文件结构。

## 手测清单

测试前提:准备一个带 datapatch 的模组组合(会修改建筑/单位属性),并保留一个未被修改的内容作对照。

1. **加载与设置(独立形态)**
   - 模组正常加载;设置 → 模组分类中出现 PatchViewer 分组,设置项完整:总开关、快捷显示模式、HUD 透明度 / 宽度 / 背景色、四个差异颜色(带预览与"默认"按钮)。
2. **数据库差异视图**
   - 进入一局后打开数据库/内容信息:被 datapatch 修改的内容显示 `原值 -> 新值`,删除显红、修改前金/后绿、新增显绿(默认配色);未修改内容与原版显示完全一致(图标大小、点击跳转不变)。
   - 描述与详情文本的增/删/改正确染色;宽度不足时箭头留在旧值行,只有新值换行。
   - 主菜单(进局前)打开同一内容:与原版一致,无差异(基线之外的 after 快照尚不存在)。
3. **快捷差异 HUD(cursor 模式)**
   - 局内长按左 Alt(默认键位),鼠标指向被修改的建筑/单位:出现跟随鼠标的 HUD,分组 Added / Modified / Removed 正确,物品堆叠带图标与数量。
   - 指向无差异内容或空地:HUD 消失;打开任意对话框/输入框时 HUD 不出现。
4. **建造栏注入(buildinfo 模式)**
   - 切换快捷显示模式为"建造栏":选中/悬停可放置方块时,差异表注入建造栏信息底部;无差异时不留空行。
5. **开关行为**
   - 关闭总开关后:内容信息完全回到原版样式,快捷差异不再触发;重新开启后恢复。
6. **颜色自定义**
   - 四个颜色项分别输入命名色(`gold`)与十六进制(`#ffd700`)即时生效;非法输入显示"无效"并回退;"默认"按钮恢复出厂值。
7. **MI2U 兼容**
   - 安装 MI2U 并开启 `replaceTopTable`:快捷差异仍能跟随 MI2U 悬停的建筑,注入模式写入 MI2U 的 `buildt` 表。
8. **多语言**
   - 切换 zh_CN / zh_TW / en(及 es / fr / ru)检查设置标题与差异分组文案正常,无裸 key。
9. **安卓包**
   - 安装 `dist/PatchViewer-vX.Y.Z.jar`(含 `classes.dex`)于安卓设备,能加载并重复第 1–5 项关键操作。
10. **聚合形态(改动 `init()` / `buildSettings()` 或 bundle 时必测)**
    - 回 Neon 同步(`python tools/update_submods.py --only pv --verify-build`)后,确认注入断言通过、Neon 总设置页出现 PatchViewer 分组且开关 key 复用生效。
